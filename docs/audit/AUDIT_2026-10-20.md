**Why the API suite failed — not product regressions, fixture state.** The dev
DB currently holds **1 user** and none of the seeded test accounts (`admin`,
`sarah.sales`, `cindy.cfo`, …). The suite's failures are almost entirely
`test fixture missing user X` / `Invalid credentials` (helpers log in with
`ChangeMe!2026` against seeded accounts). This matches SEC-006: the DB-backed
suite requires a freshly **migrated + seeded** DB, which CI now provisions but
this local dev DB is not.

**New finding (this audit): the seed itself is not re-runnable.** `db:seed`
fails on `financial_periods_company_id_code_key` when the DB already contains
finance master data (seeded here for EFRIS work). The "idempotent seed" claim in
the prior audit holds only for a pristine DB, not a partially-seeded one. Until
this is fixed the local DB-backed suite cannot be brought to green without a
destructive `db:reset`.

## 1. Architecture summary (from source)

- **Monorepo** (npm workspaces): `apps/api` (Express 5 + TypeScript), `apps/web`
  (React 18 + Vite), `packages/db` (raw-SQL migrations + seed), `deploy/` (shell
  + compose + Caddy).
- **API stack**: `pg` (raw SQL), `bcryptjs` (cost 10), `jsonwebtoken`,
  `otplib` (TOTP), `bullmq` + `ioredis` (worker queue), `helmet`, `cors`,
  `express-rate-limit`, `multer`, `zod` (dependency only — **not used** for
  validation), `qrcode`, `exceljs`.
- **Data layer**: `apps/api/src/db.ts` wraps every query in a transaction and
  calls `set_app_context(tenant, company, branch, user)`; RLS policies keyed on
  those GUCs. Pool connects as least-privilege `hopedesign_app`
  (`NOBYPASSRLS`) with a production fail-fast gate on weak/owner credentials.
- **Auth**: JWT access tokens (`type:'access'`, `tid`/`sub`/`sid`), SHA-256
  hashed refresh tokens in a revocable `sessions` table, email/WhatsApp OTP +
  TOTP MFA, RBAC (`can()` deny-by-default) + ABAC policies + SoD + workflow
  approvals.
- **Domains present** (route/services): CRM/Sales, Procurement, MRP, Inventory,
  Manufacturing (two parallel modules: `production.ts` + MES
  `manufacturing.ts`), Finance/GL/AR/AP/Payroll, HR/HCM, Security printing, QR
  traceability, Service Desk, Governance/Compliance, plus integrations (URA
  EFRIS, Hikvision, KCB, Equity, PDPO, Resend, Africa's Talking, Meta WhatsApp,
  Niimbot).
- **Infra**: Docker Compose (Postgres 16 + Redis 7), Caddy auto-TLS + HSTS/CSP,
  nginx static SPA, BullMQ worker with its own `/health`, WireGuard peer
  topology with a physical standby + failover agent, nightly backups + DR test.

## 4. Positive controls confirmed (do not regress)

- **Double-entry balancing enforced in the DB** (`post_journal` refuses `debit <> credit`,
  `0010:224-236`; re-checked on workflow path `0083:63-67`). No path writes
  `journal_lines` without a balance check.
- **Atomic financial posting** — `tx()`/`query()` wrap BEGIN/COMMIT with rollback;
  AR/AP subledger updates are in the same transaction as the GL posting
  (`finance.ts:461-530`, `sales.ts:905`). Posted transactions are **reversed/voided**,
  never silently edited (`voidJournal`, `reverse_journal()`).
- **Negative-stock and reservation guards at DB layer** (`post_inventory_move`
  insufficient-on-hand; `reserve_stock` `FOR UPDATE`).
- **Auth hardening**: bcrypt cost 10, hashed refresh tokens, revocable sessions,
  login lockout, CSPRNG + hashed OTP, deny-by-default RBAC, RLS tenant isolation,
  SECURITY DEFINER bridges `REVOKE FROM PUBLIC`.
- **Least-privilege DB role + production fail-fast boot gate**; secrets gitignored,
  generated randomly, `0600`; gitleaks + `npm audit` in CI.
- **Webhook auth**: KCB/Equity RSA signature, Meta HMAC-SHA256, Resend Svix with
  replay window — all fail-closed.
- **Idempotency present** on KCB/Equity IPN, Hikvision dedupe, WhatsApp/Resend
  inbound, MFA code supersede/consume, EFRIS `idempotency_key`.
- **Deployment**: comprehensive healthchecks, `restart: unless-stopped`, no DB/Redis
  host-port exposure, blue-green flip with health gate + rollback, advisory-lock
  single-flight workers, bounded retries/backoff across EFRIS/email/notifications.

## 5. Proposed implementation plan (phased)

> Per the master prompt: present the plan and get sign-off before large changes.
> Each item is small and reviewable with a regression test where feasible.

### Phase A — stop the silent-corruption vectors (highest value, lowest risk)
1. **INV-1/2/13** Remove `inventory`, `inventory_movements`, `inventory_reservations`
   from the generic CRUD registry, or lock their writable columns to empty in
   `crudFactory.writableOf`. *Acceptance:* PATCH/POST on those entities is rejected
   for `warehouse_manager`/`inventory_officer`; balances change only via
   `post_inventory_move()`.
2. **INV-3 + DB-10** Attach `audit_row` trigger to `inventory`,
   `inventory_movements`, `inventory_layers`, `product_batches`, `journal_lines`,
   `bank_transactions`.
3. **DB-1/2/3** Replace destructive `ON DELETE CASCADE` on GL/payroll/price-history/
   item-detail tables with `ON DELETE RESTRICT` (or soft-delete semantics), via a new
   migration. *Acceptance:* deleting a POSTED journal entry / employee / GRN header
   raises instead of cascading.

### Phase B — move external I/O out of transactions (availability + correctness)
4. **WK-1/2/3/4** Refactor `processFiscalRow`, `emailQueueFlush`/outbox drain,
   `notifyUsers`/`insertOutboundEmail`, and Hikvision provisioning/sync so every
   `fetch` (URA, Resend, ISAPI) runs **outside** `BEGIN…COMMIT`. The codebase
   already shows the correct pattern (`processNotificationDeliveries`,
   `communication.ts:771-923`). *Acceptance:* no provider HTTP between BEGIN and
   COMMIT; a hung provider no longer holds a pooled connection.

### Phase C — authorization & secret hardening
5. **SEC-A** Move the weak-default gate from `NODE_ENV==='production'` to "always
   require explicit non-default secrets unless `env === 'test'`".
6. **SEC-B** Make `crudFactory.scope()` fail-closed (`1=0`) for scope-less
   non-admins, matching `authorize.ts`.
7. **SEC-E** Return the reset token only out-of-band (or mark it one-time +
   short-TTL), never in the API response body.

### Phase D — finance/EFRIS correctness
8. **FIN-1** Add the period-open check inside `post_journal` (DB-level, mirroring
   `0083:74-76`).
9. **FIN-2** Add `UNIQUE (tenant_id, doc_ref_type, doc_ref_id)` where the doc type
   is uniquely fiscalised; make `registerEfrisDocument` insert
   `ON CONFLICT DO NOTHING`.
10. **FIN-3** Wrap `pollCreditNoteApplications` FISCALIZED branch in a transaction.
11. **WK-5** Register the EFRIS credit-note poller in `SCHEDULED_TASKS`.

### Phase E — CI/CD & operations
12. **OPS-1** Gate `production.yml` on test/security/build success (GitHub
    `needs:`/branch protection).
13. **OPS-2** Fix `build.yml` (`--target api`; add/remove the web step).
14. **OPS-3** Encrypt backups (`age`/`gpg`) + set `StrictHostKeyChecking=yes` with
    pinned host keys.
15. **OPS-6/7** Fix `restore.sh` to resolve the current primary + add integrity
    check; align `dr-test.sh` to `postgres:16`.

### Phase F — schema hardening (batched, higher risk — needs DB-verified tests)
16. **DB-4** Add CHECK constraints on qty/amount columns.
17. **DB-5** Add `WITH CHECK (tenant_id = app_tenant_id())` to RLS policies.
18. **DB-6/7** Add FKs + indexes on actor/soft-ref and FK columns.
19. **SEED-1** Make the seed idempotent against partial data (or fail with a clear
    "reset required" message).
20. **SEC-F** Introduce zod schemas incrementally for the highest-risk endpoints.

## 7. Production deployment & rollback checklist

- **Pre-deploy:** CI (tests + `npm audit` + gitleaks + build) green; backups
  verified (`gzip -t`); migration diff reviewed as expand-only.
- **Deploy:** blue-green flip via `zero-downtime-deploy.sh`; gate on
  `GET /api/health` `status:ok` through Caddy; monitor worker `/health`.
- **Rollback:** `rollback.sh` reverts the Caddy flip; DB rollback requires a
  pre-taken snapshot (`pg_dump`) because migrations are forward-only — do **not**
  rely on schema rollback.
- **Post-deploy:** confirm backup freshness, offsite sync md5, watchdog heartbeat,
  and no stuck jobs (EFRIS queue, email outbox, notification dispatcher).

## 8. Open items needing a decision (not code)
